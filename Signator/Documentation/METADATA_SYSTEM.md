# 451 Protocol Metadata System

## Overview

The 451 Wallet now includes a comprehensive metadata system aligned with the full 451 protocol specification. This metadata structure is based on Dublin Core standards and scholarly publishing practices, supporting rich document descriptions for contracts, academic papers, books, and other document types.

## Key Files

### Core Metadata

**`DocumentMetadata451.swift`**
- Primary metadata structure with all 451 protocol fields
- Supports Dublin Core elements (title, creator, subject, description, etc.)
- Includes identifiers (DOI, ISBN, ISSN, DIDs)
- Structured signer information with roles
- Optional fields - only include what you need

### UI Components

**`DocumentMetadataEditor.swift`**
- Full metadata editor with collapsible sections
- `DocumentMetadataEditor` - Comprehensive form with all fields
- `CompactMetadataEditor` - Simplified form with essential fields only
- `DocumentMetadataForm` - Observable model for data binding

### Service Integration

**`DocumentSigningService.swift`** (updated)
- `uploadDocument()` now accepts optional `DocumentMetadata451` parameter
- Metadata sent as multipart/form-data when provided
- All workflow methods support metadata:
  - `completeSigningWorkflow()`
  - `completeSigningWorkflowWithProgress()`
  - `completeSigningWorkflowWithSSEProgress()`

### Examples

**`CompleteDocumentUploadExample.swift`**
- Complete example view showing metadata collection and upload
- Simple helper function `uploadDocumentToServer()` for quick uploads
- Multiple usage examples in code comments

## Metadata Fields

### Required
- `title` - Document title (only truly required field)

### Core Identifiers
- `id` - UUID generated by client or server
- `did` - Decentralized identifier (did:local:*, did:451:*)
- `doi` - Digital Object Identifier
- `isbn` - International Standard Book Number
- `issn` - International Standard Serial Number
- `identifier` - Generic identifier field

### Descriptive
- `title` - Primary title
- `subtitle` - Secondary title
- `description` - Abstract or full description
- `subject` - Keywords, topics (comma-separated)
- `type` - Document type (contract, article, book, report, etc.)
- `language` - Content language (ISO 639 codes)
- `transcript` - Full transcript for audio/video

### Responsibility
- `author` - Primary author(s)
- `contributor` - Additional contributors
- `publisher` - Publishing organization
- `signers` - Structured array of signers with roles

### Rights & Access
- `rights` - License or rights statement
- `rightsholder` - Rights holder
- `accessrights` - Access level (public, private, restricted, confidential)

### Dates
- `publicationDate` - ISO 8601 date string
- `dateAvailable` - Date document becomes available

### Audience & Context
- `audience` - Target audience
- `audiencemediator` - Intermediary
- `provenance` - Historical ownership/custody record

### Technical
- `format` - Format description (451, PDF, DOCX, etc.)
- `fileExtension` - Original file extension
- `mimeType` - MIME type
- `fileSize` - Size in bytes
- `documentHash` - Cryptographic hash

### Custom
- `contractId` - Contract-specific ID
- `tags` - Array of custom tags
- `customFields` - Dictionary of custom key-value pairs

## Signer Roles

The metadata supports structured signer information with the following roles:

- `author` - Document author/creator
- `contractParty` - Party to a contract/agreement
- `witness` - Witness to signing
- `notary` - Notary public
- `reviewer` - Reviewer/approver

Example:
```swift
let signers = [
    DocumentMetadata451.SignerMetadata(
        did: "did:example:alice",
        role: "author",
        publicKey: "...",
        displayName: "Alice Smith"
    ),
    DocumentMetadata451.SignerMetadata(
        did: "did:example:bob",
        role: "contractParty",
        displayName: "Bob Jones"
    )
]
metadata.signers = signers
```

## Usage Patterns

### Pattern 1: Simple Upload with Minimal Metadata

```swift
let documentId = try await uploadDocumentToServer(
    documentData: pdfData,
    filename: "contract.pdf",
    title: "Employment Contract",
    author: "John Doe",
    documentType: "contract"
)
```

### Pattern 2: Full Metadata Collection with UI

```swift
struct MyUploadView: View {
    @State private var metadataForm = DocumentMetadataForm()
    @State private var showMetadataEditor = false
    
    var body: some View {
        Button("Edit Metadata") {
            showMetadataEditor = true
        }
        .sheet(isPresented: $showMetadataEditor) {
            NavigationStack {
                DocumentMetadataEditor(metadata: $metadataForm)
                    .toolbar {
                        ToolbarItem(placement: .confirmationAction) {
                            Button("Done") { showMetadataEditor = false }
                        }
                    }
            }
        }
    }
    
    func upload() async throws {
        let metadata = metadataForm.toMetadata()
        let (documentId, _, _) = try await DocumentSigningService.completeSigningWorkflow(
            documentData: documentData,
            originalFilename: filename,
            metadata: metadata
        )
    }
}
```

### Pattern 3: Programmatic Metadata Creation

```swift
var metadata = DocumentMetadata451()
metadata.title = "Research Paper"
metadata.subtitle = "AI in Healthcare"
metadata.author = "Dr. Jane Smith"
metadata.description = "Comprehensive study of AI applications"
metadata.subject = "AI, Healthcare, Machine Learning"
metadata.type = "article"
metadata.language = "English"
metadata.doi = "10.1234/example.doi"
metadata.publicationDate = ISO8601DateFormatter().string(from: Date())

// Add signers
metadata.signers = [
    DocumentMetadata451.SignerMetadata(
        did: "did:example:jane",
        role: "author",
        displayName: "Dr. Jane Smith"
    )
]

let (documentId, _, _) = try await DocumentSigningService.completeSigningWorkflow(
    documentData: paperData,
    originalFilename: "paper.pdf",
    metadata: metadata
)
```

### Pattern 4: With Progress Tracking

```swift
let (documentId, attestEntryID, accessCode) = try await DocumentSigningService.completeSigningWorkflowWithSSEProgress(
    documentData: documentData,
    originalFilename: filename,
    metadata: metadata,
    onProgress: { update in
        print("Client: \(update.progress * 100)% - \(update.message)")
    },
    onServerProgress: { serverUpdate in
        print("Server: \(serverUpdate.progress * 100)% - \(serverUpdate.message)")
    }
)
```

## Server Integration

The metadata is sent to the server as JSON in a multipart/form-data request:

```
POST /api/document/publish
Content-Type: multipart/form-data; boundary=...

--boundary
Content-Disposition: form-data; name="document"; filename="document.pdf"
Content-Type: application/octet-stream

[binary document data]
--boundary
Content-Disposition: form-data; name="metadata"
Content-Type: application/json

{
  "title": "Document Title",
  "author": "Author Name",
  "type": "contract",
  "description": "...",
  "signers": [
    {
      "did": "did:example:alice",
      "role": "author",
      "displayName": "Alice"
    }
  ]
}
--boundary--
```

If no metadata is provided, the upload falls back to simple `application/octet-stream` with an `X-Original-Filename` header.

## Migration from Legacy Metadata

The system includes a compatibility layer for migrating from the old `DocumentMetadata` structure:

```swift
let legacyMetadata = metadata451.toLegacyMetadata()
```

This creates a `LegacyDocumentMetadata` instance with the old structure for backward compatibility.

## Best Practices

1. **Always provide a title** - It's the only field that should be considered required
2. **Add author information** - Helps with attribution and search
3. **Include description** - Makes documents more discoverable
4. **Set document type** - Helps with categorization
5. **Use structured signers** - Better than comma-separated strings
6. **Add identifiers** - DOI, ISBN, etc. when applicable
7. **Set access rights** - Clear indication of document privacy level
8. **Use ISO standards** - ISO 8601 for dates, ISO 639 for languages
